- [11:30] (Alek) fix: MCP server processes (start + test) now inherit login shell environment via `get_login_env()`. Root cause: `mcp.rs` was the only spawn site NOT using `shell_env.rs`, so GUI-launched Quack had minimal PATH. Ref: `gotcha-shell-env-gui-launch`.
- [11:45] (Alek) fix: MCP test_stdio_connection replaced `child.wait()` with `try_wait()` polling loop. Root cause: Tokio's `Child::wait()` closes stdin before waiting (deadlock prevention), causing MCP stdio servers to see EOF and exit with code 1. `try_wait()` is non-blocking and does NOT close stdin, so the server stays alive during the 2s test window. Also added stderr capture for better error diagnosis when a server does crash.
- [12:50] (Alek) fix: code-intel MCP was missing from `stream-daemon.js`. It was added to `stream-claude.js` (legacy) but never to the persistent daemon. Only worked in quack-app because the project `.mcp.json` had it as a fallback. Now added as built-in alongside `ide-tools`.
- [14:30] (Alek) feat: Added Swift language support to code-intel MCP. Installed `tree-sitter-swift`, updated all 6 modules (parser, walker, outline, definitions, references, imports). Swift AST uses `class_declaration` for class/struct/enum/extension/actor (keyword child differentiates). Identifiers use `simple_identifier` instead of `identifier`. Properties use `pattern` child for names. Extension names are inside `user_type > type_identifier`. Modifiers (public/private) come before keyword in children order. Tested: outline, find_definition, find_references, get_imports all work correctly on Swift code. No TS/JS regression.
