- [15:25] (Alek) **Office V2 bugfix: una card per progetto, non per agente** (commit `2d9844b`).
  - **Sintomo**: nella PERSONAL WING comparivano 3+ card "AGENT JACK" / "AGENT ALEX" / "AGENT SOPHIE" ecc. invece di una sola card "quack-app" con i duck degli agenti al suo interno.
  - **Root cause 1**: `bootstrapLayoutFromTerminals` e `reconcileLayoutWithTerminals` iteravano `terminals.filter(...)` senza dedup per `cwd`. Se 3 agent condividono lo stesso progetto, venivano create 3 `OfficeRoomCard` con lo stesso `projectPath` ma posizioni diverse.
  - **Root cause 2**: `OfficeRoomCard` mostrava `terminal.label` (il nome dell'agent) come titolo della card. Quindi i duplicati apparivano come "JACK JACK JACK" invece di 3 copie di "quack-app", rendendo il bug meno ovvio.
  - **Fix**:
    1. `officeMigration.ts` → helper `uniqueProjectPaths(terminals)` usato in `buildRoomsForZone` e dentro il loop di `reconcileLayoutWithTerminals`. Aggiunto **dedup retroattivo** all'inizio di reconcile: se il layout persistito contiene già duplicati (cosa accaduta nei JSON salvati prima di questo fix), vengono rimossi mantenendo la prima occorrenza.
    2. `OfficeRoomCard.tsx` → prop `terminal: TerminalInfo` sostituita con `projectName: string` + `branch?: string`. La door plate ora mostra `projectName`.
    3. `OfficeCanvas.tsx` → deriva `projectName` via nuovo helper `projectNameFromPath()` in `officeLayout.ts`; il branch viene preso dal primo terminal del progetto con `branch` definito.
    4. Test: +3 test in `officeMigration.test.ts` (dedup bootstrap, dedup reconcile, dedup retroattivo layout corrotto). Tutti 9 test passano.
  - **Impatto utenti**: il primo avvio dopo il fix auto-ripulisce il `office-layout.json` esistente grazie al dedup retroattivo in reconcile. Nessuna azione manuale richiesta.
