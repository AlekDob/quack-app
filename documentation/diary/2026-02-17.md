- [10:16] (Alek) Fixed Brain Timeline not showing entries without YAML frontmatter. Root cause: Agent Evan wrote gotcha/pattern/diary files in calendar project without `---` frontmatter block, so `parseBrainFile` returned null. Three fixes: (1) added frontmatter to the 4 missing files, (2) added `Preferred Skills: quack-brain` to calendar's CLAUDE.md so agents load the format spec, (3) made `parseBrainFile` resilient — infers type from path and date from filename when frontmatter is missing. KEY INSIGHT: `parseBrainFile` should never silently drop valid .md files just because frontmatter is missing — infer what you can from the filesystem.
- [10:23] (Alek) Injected Display Name into agent header via `personality.rs`. New `read_display_name_from_global_claude_md()` reads `**Name**: Alek` from `~/.claude/CLAUDE.md` and injects `**Diary Author**: Alek` with explicit instruction into every project CLAUDE.md agent header. Prevents agents from using their own name (e.g. "Agent Evan") as diary author. KEY INSIGHT: Agent identity (`Your name is **Agent Evan**`) overrides the global `**Name**` in the LLM's mind — the diary author must be explicitly stated in the agent header itself, not just in a separate file.
- (Alek) New Droid/Rule creation flow: replaced internal editor with ScopePickerModal (name + project/global scope) → creates draft file on disk with template content → opens in preferred IDE if set, otherwise fallback to internal tab. Files: `ScopePickerModal.tsx` (new), `AgentsPanel.tsx`, `RulesPanel.tsx`, `rules.rs` (create_rule now returns file path). KEY INSIGHT: reuse `handleSelectDroid(name, scope, false, filePath)` with `isNew=false` — the file exists on disk, so the existing IDE-or-tab logic handles everything without new code in App.tsx.
- (Alek) Added Edit/Delete hover buttons to droids (AgentsPanel) matching the existing RuleItem pattern. Delete uses new `ConfirmModal` React component instead of `window.confirm()`. KEY INSIGHT: `window.confirm()` is unreliable in Tauri WebView — it doesn't block the JS thread properly, causing deletions before user confirms. See `gotcha-window-confirm-tauri-webview.md`.
- (Alek) Windows compatibility fix in `rules.rs`: replaced all 7 occurrences of `std::env::var("HOME")` with cross-platform `get_home_dir()` (HOME || USERPROFILE). The `agency.rs` file already had this — `rules.rs` was the last holdout.
