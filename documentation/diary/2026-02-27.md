New endpoints: `POST /api/jobs` (create), `PUT /api/jobs/:id` (update), `DELETE /api/jobs/:id` (delete), `DELETE /api/sessions/:id` (delete session + SDK file cleanup). - [16:00] (Alek) fix(remote-chat): Mobile chat not receiving agent responses + persistent typing indicator. Root cause: session ID mismatch — Rust generated `session-{UUID}` and returned it to mobile, but React `createSession()` generated its own `session-{timestamp}-{random}` ignoring the Rust ID. Mobile polled with wrong ID → always got empty messages. Fix: `createSession` now accepts optional `id` param; `remote-execute` listener passes Rust's `sessionId` through. Also fixed `openChat` to fetch session status alongside messages on initial load (prevents stale typing indicator).
- [16:30] (Alek) fix(automation): "Scheduler already running" log spam on dev startup. Root cause: `useEffect` in App.tsx:9208 has unstable deps (`createSession`, `sendMessageForTargetAgent`) that change identity every render → re-runs effect → calls `start_automation_scheduler` hundreds of times. Scheduler is idempotent (returns early) but logged at `info` level, flooding console. Fix: changed `log::info!` → `log::debug!` in `automation.rs:97`. Deeper fix (stabilize deps with useRef) deferred.
