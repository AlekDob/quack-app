- [10:00] (Alek) fix(remote): white screen on mobile dashboard after WiFi change — IP changed but PWA URL was hardcoded. Verified server was running and accessible via new IP. Root cause: no `?token=` in URL → `window.__QUACK_TOKEN__` injected as empty string → all API calls 401.
- [10:15] (Alek) feat(remote): added mDNS hostname discovery for stable dashboard URLs. New Rust command `get_local_hostname()` returns `{hostname}.local` (works on macOS Bonjour + Windows 10+ natively). Dashboard URL now uses `.local` hostname instead of IP — survives WiFi/network changes.
- [10:30] (Alek) feat(settings): added "Mobile Dashboard" section in Remote API settings. Shows full copyable URL (`http://hostname.local:port/dashboard?token=xxx`) with one-click copy. Info box explains mDNS stability. Falls back to IP-based URL if hostname unavailable.
- [11:00] (Alek) setup: Installed GitHub Spec-Kit CLI v0.1.6, initialized `.specify/` with Quack Constitution v1.0.0 (7 principles)
- [11:15] (Alek) feat(settings): Claude Code Memory Settings — new "Memory" section in Claude Code settings with auto-memory toggle (reads/writes `~/.claude/settings.json`), env var override detection, and "Open Memory Folder" button. 3 new Rust commands: `get_claude_settings_flag`, `set_claude_settings_flag`, `open_claude_memory_folder`
- [15:30] (Alek) feat(remote-api): Full CRUD for automation jobs + session delete. New endpoints: `POST /api/jobs` (create), `PUT /api/jobs/:id` (update), `DELETE /api/jobs/:id` (delete), `DELETE /api/sessions/:id` (delete session + SDK file cleanup). Added frontend sync listeners for `automation-jobs-updated` and `sessions-updated` events so React state reloads when API makes changes. Updated quack-remote skill and pattern doc.
- [16:00] (Alek) fix(remote-chat): Mobile chat not receiving agent responses + persistent typing indicator. Root cause: session ID mismatch — Rust generated `session-{UUID}` and returned it to mobile, but React `createSession()` generated its own `session-{timestamp}-{random}` ignoring the Rust ID. Mobile polled with wrong ID → always got empty messages. Fix: `createSession` now accepts optional `id` param; `remote-execute` listener passes Rust's `sessionId` through. Also fixed `openChat` to fetch session status alongside messages on initial load (prevents stale typing indicator).
- [16:30] (Alek) fix(automation): "Scheduler already running" log spam on dev startup. Root cause: `useEffect` in App.tsx:9208 has unstable deps (`createSession`, `sendMessageForTargetAgent`) that change identity every render → re-runs effect → calls `start_automation_scheduler` hundreds of times. Scheduler is idempotent (returns early) but logged at `info` level, flooding console. Fix: changed `log::info!` → `log::debug!` in `automation.rs:97`. Deeper fix (stabilize deps with useRef) deferred.
- [18:00] (Alek) fix(automation): job non rispettava model e provider selezionati. Root cause: `sendMessageForTargetAgent` usava `getProviderRequestFields()` che legge il provider globale — ignorava completamente il model/provider del job. Un job con `kimi-k2.5:cloud` (Ollama) partiva con Opus 4.6 (Anthropic). Fix: aggiunto campo `provider` a `AutomationJob`, salvato dal form, propagato a `sendMessageForTargetAgent` via `ChatSendOptions.provider`. Fixato in entrambi i path (fire manuale + scheduler tick). Anche: sessione "Untitled" fixata con fallback difensivo + salvataggio `claudeSessionId` nel session store dopo completamento.
- [19:00] (Alek) feat(remote-chat): optimistic messages — messaggi utente restano visibili durante polling (flag `_optimistic: true`), loader/typing indicator mostrato quando ultimo messaggio è `user`. Fix messaggio duplicato "Ciao" in `executeFromDrawer` (mancava flag `_optimistic`).
- [19:15] (Alek) feat(remote-chat): model selector nel drawer mobile. Pipeline: `<select>` → POST `/execute` con `model` → Rust `ExecuteRequest.model: Option<String>` → Tauri event → React `pendingAutoStartRef.model` → `sendMessageForAgent({ model })`. Default "Default (agent preset)" con valore vuoto → usa modello preconfigurato dell'agente.

- [20:30] (Alek) fix(remote-execute): doppia inizializzazione sessione da mobile. Root cause: React Strict Mode + async `listen()` cleanup race → due listener attivi, entrambi creano sessione. Fix iniziale con `pendingAutoStartRef` dedup non funzionava (async race). Fix definitivo: `handledRemoteSessionIds` ref con `Set<string>` sincrono, checked/updated prima di qualsiasi `await`.
