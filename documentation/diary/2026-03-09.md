- [15:55] (Alek) fix: propagate Bedrock/Vertex/AWS env vars from login shell to SDK child processes. When Quack is launched from Finder, cloud provider env vars (CLAUDE_CODE_USE_BEDROCK, AWS_PROFILE, etc.) were missing from SDK spawn, causing "400 The provided model identifier is invalid" for Bedrock users. Added `propagate_cloud_env()` helper + `CLOUD_PROVIDER_ENV_VARS` const in claude_cli.rs. Reported by Discord user Netivski.
- [17:30] (Alek) fix: AuthDebugPanel now reads env vars from login shell too, so `CLAUDE_CODE_USE_BEDROCK` shows correctly even when Quack launched from GUI. Bumped version to 0.7.1 for hotfix release.
- [17:40] (Alek) fix: model ID mapping fallback. When Supabase is unreachable, `opus46` was sent as-is to API causing "invalid model" error. Added Supabase ID mappings (`opus46`→`claude-opus-4-6`, etc.) as safety net in `stream-claude.js:getModelId()`. Also expanded `EMERGENCY_FALLBACK` in `modelService.ts` to include all current models.
