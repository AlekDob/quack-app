- [13:00] (Alek) Fix definitivo avatar papero: il `paperoId` era nell'evento `thread.message-sent` ma NON nella projection SQL (`projection_thread_messages` non aveva la colonna), quindi appena il messaggio ottimistico veniva riconciliato con quello del server la timeline perdeva l'agente e ricadeva su Milo (`DEFAULT_PAPERO_ID`). Aggiunta migration 089 + colonna `papero_id` propagata in upsert/append-streaming, row codec e le 4 SELECT (repository + snapshot query).
- [13:05] (Alek) Riga identità del turno in chat: accanto all'avatar ora compaiono nome agente, modello e effort **di quel turno**. La selezione a livello thread viene sovrascritta dal turno successivo, quindi il decider stampa `modelSelection` sul messaggio utente (evento + projection: migration 090, colonna `model_selection_json`). Lato web `ChatMessage.modelSelection` viaggia fino alle righe timeline (`avatarModelSelection`) e viene reso dal componente condiviso `PaperoStreamMetaRow` (riga flex: papero · modello · effort), usato sia dalla riga assistant sia da "Thinking". Confronto identity-tolerant (`optionalModelSelectionsEqual`) per non far churnare le righe a ogni decode.

In più, dentro un thread subagent lo stream mostra la papera + label del subagent invece del papero di default: nuovo file condiviso `ChatStreamIdentity.tsx` (`ChatStreamAvatarSlot` + `ChatStreamMetaRow`, prima in `PaperoPill`), con `subagentStreamAvatarSeed`/`subagentStreamLabel` passati da ChatView. Fix collaterale: `flushStorageBeforePageHide` ora controlla `typeof addEventListener === "function"` (uno stub DOM parziale nei test faceva crashare l'import).
