- [10:00] (Alek) fix(stamina): Replaced static overhead estimate with precise measurement using Anthropic `countTokens` API. Root cause: `calculateProjectOverhead()` estimated ~35k but real overhead was 60k+ (missed rules files, skills, MCP tool definitions). New approach: Node.js daemon calls `countTokens({ model, messages: [userPrompt] })` (FREE API) in parallel with the query, emits `prompt_token_count` event to frontend. Frontend calculates `measuredOverhead = contextWindowFill - promptTokens` on first turn, caches it for the session. **KEY**: countTokens API is free, runs in parallel (no latency), and gives exact token count. Static estimate kept as fallback for Ollama/custom providers. Updated both `stream-daemon.js` and `stream-claude.js` (dual-path gotcha). See `documentation/gotchas/gotcha-stamina-overhead-static-estimate.md`.
- [11:00] (Alek) refactor(context-receipt): Removed inaccurate breakdown section (Messages/Overhead/Auto-Compact) from Context Receipt modal. The total % was correct but the breakdown was misleading (showed Messages: 22k vs real 663). Now single-column layout with emphasis on percentage (28px). Cleaner, more honest UI.

Quack already has `ENABLE_TOOL_SEARCH: 'auto'` for MCP tools. Future opportunity: tool profiles per agent role (~5-8k savings), lazy-load non-core built-in tools (~3-5k), conditional system prompt append (~1-2k). Total potential: 4-6% context freed.
