re-deriving from the full activity history on every live-activity tick

still derive from their distinct parent source, since they need it either way.

manual reload. This flow had no feature doc yet — wrote one:

## Explorer files are editable

Picked upstream #568. Explorer file panes now take `editable`, and Cmd/Ctrl+S
saves in place. The interesting part is what it does _not_ do: saving sends the
`sha256:` version the file had when it was opened, and the server re-reads and
re-hashes just before the atomic rename. A file changed on disk in the meantime
is refused with a conflict error instead of last-write-wins. Deleted files get
their own error. Encoding (UTF-8 BOM) and line endings are preserved rather
than normalized, and files with mixed line endings are read-only on purpose.

The path-containment guard on writes already existed; this only stacks
concurrency checks on top of it.

Server tests 25/25, new browser tests 4/4, typecheck error count unchanged.
`oxfmt` rewrote the four incoming files (upstream doesn't run our formatter on
everything), so that's folded into the same commit.

New doc: [020-workspace-file-preview.md](../features/020-workspace-file-preview.md).

## iOS Simulator pane imported

Took `467d2f218` (#529). It is not a small commit: 120 files, ~22.5k lines,
including a native Swift/ObjC helper that talks to CoreSimulator private APIs.
Despite the size, only 4 files conflicted, because ~110 of them are new.

Conflicts and how they were settled:

- `harnessPolicy.ts` — the real one. Our fork renamed Synara to Quack in the
  agent policy text; upstream's version had its own branding and a different
  OAuth-popup paragraph. Kept our branding and our paragraph, took the device
  guidance with "Synara" rewritten to "Quack", bumped the version to
  `2026-08-11.1`. No test asserts on the branding, so nothing broke.
- `icons.tsx` — upstream also swapped the app globe to a Central glyph, which
  has nothing to do with iOS. Kept our globe, took only the `Device*` icons.
- `shortcutsSheet.ts` — upstream's hunk carried both `device.toggle` and
  `thread.copyId`. The second belongs to a commit we have not imported and has
  no command behind it, so it was dropped.
- `wsNativeApi.ts` — adjacent imports, kept both.

One real defect from the merge: `serverLayers.device.test.ts` failed typecheck
because our `ThreadId` is branded and upstream's is a plain string. Added the
cast; server errors went back from 38 to the pre-existing 37.

No regressions. Same failing test names as before in every package (web 10,
server 10 + `ProviderAdapterRegistry`, shared 1 — all the `astronaut` cascade
and the pre-existing ratchet entries), desktop 578/578, contracts 197/197
(+8 new device tests). Lint went 383 -> 393 warnings, and all 10 are inside the
new upstream device files; the four files I touched added none.

`ChatView.tsx` grew 59 lines and is still over its ratchet budget, but it was
already over before this pick, so no new failing test. Worth flagging: the
budget file is the thing that says "extract, do not raise", and ChatView is now
further from it than ever.

Note for later: `bun typecheck` SIGKILL'd twice while I had `tsc` running in
parallel. It is memory, not the import — a clean sequential run fails exactly
like the baseline (contracts, 7 astronaut errors).

  copy-thread-ID shortcut, image overlay layering, `backdrop-filter` in prod

  stale git refresh + merged-PR badges, AskUserQuestion recovery, worktree setup
  cancel, GitHub project import, iOS Simulator pane, and others.

Everything that conflicts lands on the same handful of files our fork diverged
on: `ChatView.tsx`, `Sidebar.tsx`, `OrchestrationEventStore.ts`, `index.css`.
Cherry-picking one at a time gets more expensive from here, not less — a real
merge of `upstream/main` on a dedicated branch is the cheaper path, and it
brings both tiers along for free.
