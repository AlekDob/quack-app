- [14:00] (Alek) **Fix: il permission-mode (Auto / Auto-edit) non veniva MAI rispettato — chiedeva permessi per tutto anche in automode**. ROOT CAUSE: Quack tiene SEMPRE attivo l'hook `PreToolUse` (scelta voluta), quindi l'unico giudice frontend allow/deny è `ClaudePermissionOverlay`; ma `shouldAutoAllow` guardava solo privacy-gate, read-only e regole always-allow salvate — **non leggeva mai `ccPermMode`**. Quindi `--permission-mode acceptEdits` passato alla CLI era inerte (l'hook intercetta prima che la CLI applichi l'auto-accept). Inoltre `auto`/`dontAsk` NON sono permission-mode reali della CLI (valida solo default|plan|acceptEdits|bypassPermissions): erano etichette orfane, e lo stato di default era `"auto"` → il bottone diceva "Auto" ma si comportava da "Ask". FIX (4 file): nuovo `src/permModeStore.ts` (ponte module-level mode↔overlay, keyed by CC session id + cwd, pattern `aiTaskStore`); l'overlay ora ha `modeAutoAllow` — `auto`=allow tutto (Bash incl., privacy-gate+AskUserQuestion-redirect restano), `acceptEdits`=solo Edit/Write/MultiEdit/NotebookEdit; `AIChatPanel` pubblica il mode nello store + lo persiste (`lcp.claudeCode.permMode`) e ora **default = Ask (null)**, non più "auto" (fix mismatch label/comportamento + niente full-allow di default su install nuova). Aggiunto **mode Bypass** = `bypassPermissions` reale di Claude Code (prima RIFIUTATO dal backend): `claude_code.rs` lo whitelista, salta l'installazione dell'hook e bypassa la refusal-guard (è opt-in esplicito) → zero card, niente privacy gate. Il backend ora passa alla CLI solo `plan`/default (mai l'invalido `auto`). Rimossi i riferimenti orfani a `dontAsk`. `tsc` verde, `cargo check`+4 test verdi.
- [14:20] (Alek) **Plan mode: troppi permessi → auto-allow del Bash di sola lettura**. CHIARIMENTO ARCHITETTURALE (domanda di Alek): le regole dei permessi NON sono ereditate da Claude Code né passano da API — l'hook `PreToolUse` (sempre attivo) scavalca il permission-system della CLI e l'unico giudice è `ClaudePermissionOverlay`. I Read erano già auto (`READ_ONLY_HOOK_TOOLS`); ciò che chiedeva in plan mode era il **Bash** (sempre dietro card per design). FIX: `modeAutoAllow` ora gestisce `plan` → auto-allow Bash solo se `isReadOnlyBash`: head ∈ safelist read-only (ls/cat/grep/rg/tree/stat/wc/head/tail/echo/pwd/which/du/df/sort/uniq/cut/basename/dirname/realpath…) oppure `git` + subcomando read-only (status/log/diff/show/blame/ls-files/rev-parse/describe), e nessun `>`/`|`/`;`/backtick/`$(` (riuso `BASH_CHAIN_RE`). Safelist volutamente stretta: esclusi i runner (env/xargs/sudo), `sed -i`, e git branch/tag/config/remote (hanno forme mutanti). La CLI in plan mode già blocca le scritture, quindi l'unico rischio era il side-effect Bash → coperto. `tsc` verde. Doc aggiornata in `features/015-claude-permission-mode.md`.

- [10:00] (Alek) **Fix: premere Stop su una chat Claude Code rallentava/freezava l'app** (`src-tauri/src/claude_code.rs`). Due bug sommati. BUG 1: il thread `wait()` faceva `child.lock().wait()` tenendo il `MutexGuard` per TUTTA la durata del processo → `claude_code_kill` (e il watchdog `try_wait`) si bloccavano dietro quel lock e non riuscivano mai a uccidere finché la run non finiva da sola. In pratica lo Stop su run lunghe non funzionava. BUG 2: `Child::kill()` manda SIGKILL solo al processo `claude` padre; i sottoprocessi tool (Bash, ricerche file tipo `bfs`/`find`) restavano ORFANI (reparented a launchd) e continuavano a girare → un `bfs` a metà scansione ricorsiva resta a ~524% CPU e affossa tutto il Mac, Quack incluso. KEY INSIGHT: `bfs` (breadth-first find) visto in Attività NON era nel repo — era un figlio orfano di Claude Code. FIX: (1) `claude` lanciato in un process group dedicato (`cmd.process_group(0)` unix / `CREATE_NEW_PROCESS_GROUP` win); (2) nuova `kill_process_tree(pid)` che fa `libc::kill(-pid, SIGKILL)` (intero gruppo) su unix e `taskkill /T /F` su win; (3) la mappa `children` ora tiene solo il `u32` pid (non più `Arc<Mutex<Child>>`) → kill/watchdog non lockano mai il `Child`, di cui è proprietario solo il thread `wait()`; (4) watchdog coordinato con un `AtomicBool finished`. Aggiunta dep unix `libc`. `cargo check` verde. Gotcha salvata in `documentation/claude-stop-process-group.md`.
