# Team roster and plugin approvals

## Paperi identity

The Team roster is now the source of truth for a papero's name, avatar, role, and
instructions.

- The composer and transcript use the same roster resolver.
- Editing instructions calls `team.upsertAgent`, then refreshes the Team query.
- Legacy `synara:paperi:v1` overrides are read for migration compatibility only.
- A save confirmation appears only after the server accepts the update. Failures
  show the returned error instead of a false success message.

This keeps an edited agent consistent between the composer pill and older messages
already visible in the stream.

## MCP plugin installation

Codex `mcpServer/elicitation/request` events are handled as a pending
`plugin-install` approval.

- Accept replies with `{ action: "accept", content: {} }`.
- Decline and cancel use the Codex elicitation response shape.
- Session-wide approval does not auto-accept plugin installation requests.
- Runtime activity, attention candidates, and labels expose the new
  `plugin-install` request kind.

The server test covers the full request-to-response path. The Team resolver and
legacy paperi migration also have focused tests.
