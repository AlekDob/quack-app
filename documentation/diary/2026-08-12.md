# Companion (astronaut) typecheck cascade closed, chat hot path recompiles

## Astronaut/Companion: from ~180 typecheck errors to 0

The imported Companion provider was added to `ProviderKind` without being added to
anything that is exhaustive over it. Two root causes explained nearly every error:

1. `astronaut` was missing from every per-provider `Record<ProviderKind, …>` map and
   from every exhaustive `switch`.
2. `AstronautModelSelection` was the only `ModelSelection` member without an
   `options` field, so `modelSelection?.options` stopped typechecking everywhere.

Fixing the two causes centrally collapsed roughly 50 errors in two edits:

- `packages/contracts/src/model.ts`: added an empty `AstronautModelOptions` schema and
  wired it into `ProviderModelOptions`; `ProviderWithDefaultModel` now excludes both
  `pi` and `astronaut`.
- `packages/contracts/src/orchestration.ts`: `AstronautModelSelection` reuses that schema.
- `packages/shared/src/model.ts`: `hasDefaultModel()` became the single predicate for
  "this provider discovers its catalogue at runtime", plus a new
  `providerWithDefaultModel()` helper for the call sites that need a concrete fallback.
  Every `provider === "pi"` check in web and server now routes through those two.

Opportunistic DRY along the way: `ProfileSettingsPanel` dropped a hardcoded 20-line
provider-label switch in favour of `PROVIDER_DISPLAY_NAMES`, `projectDefaultProvider`
uses the same map for its "no available models" message, and the `serverSettings`
test fixture now spreads the defaults so a future provider cannot break it.

## React Compiler: ChatView compiles clean again

The imported features had silently knocked `ChatView.tsx` out of React Compiler
(a bailout means the whole component loses auto-memoization). Two triggers, both
listed in `chatHotPath.compiler.test.ts` and both fixed at the root:

- a `throw` inside a `try` in `onSavePaperoInstructions` — the try/catch moved to
  `savePaperoInstructionsFailure()` in `ChatView.logic.ts`, which returns a message
  instead of throwing;
- the Claude auth recovery callback: a value block read inside a `catch` closure, and
  a manual dependency list naming `activeThread?.worktreePath` where the compiler
  inferred `activeThread`. Both hoisted to consts above the callback.
