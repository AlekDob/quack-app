- [PM] (Fredric) Completed quantitative payload diff analysis for cache-breaking investigation. Wrote `scripts/cache-payload-diff.mjs` to compare 4 captured `/v1/messages` API payloads byte-by-byte. Key finding: the SDK's `ejY()` serializer strips TodoWrite reminder + `cache_control` from historical messages during re-serialization from disk, breaking the prefix at the most recent user message boundary.
- [PM] (Fredric) Discovered that the SDK's V1 `query()` API spawns a **fresh CLI subprocess per call** — each call creates a new OS process via `child_process.spawn()`. All in-memory state (skills, cache markers, message decorations) is destroyed between turns. This is why cache breaks even though the daemon stays alive.
- [PM] (Fredric) Built and ran `scripts/cache-persistent-subprocess-test.mjs` — spawns the CLI once and keeps it alive across 4 turns. Result: `cacheCreationTokens` dropped from ~28,000-33,000 to **56** per turn. Better than native CLI (~300). Theory confirmed: the fix is keeping the subprocess alive, not patching serialization. Reclassified as "Quack fix available now".
- [PM] (Fredric) Implemented `SessionProcess` class in `stream-daemon.js`. Persistent subprocess architecture: resumed sessions reuse the same CLI process across turns instead of spawning fresh via `query()`. New sessions still use `query()` as before. Includes bidirectional control_request/control_response protocol for canUseTool, init config with systemPrompt append, and graceful abort handling that preserves the subprocess for cache reuse.
