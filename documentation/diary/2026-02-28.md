- [10:15] (Alek) feat: Added third permission mode "Debug" with green color (#22c55e). Debug mode uses `bypassPermissions` SDK mode but injects systematic debugging instructions into the system prompt. Default preset: Opus 4.6, auto thinking, high effort.

- [10:30] (Alek) feat: Added Debug Mode accordion banner in ChatView — shows at top of chat when debug mode is active. Collapsed: one-line summary "Brain lookup → Root cause → Hypothesis → Fix → Document". Expanded: 4 numbered phases with descriptions.

- [10:45] (Alek) fix: Settings crash when opening Agent Mode Presets — `TypeError: undefined is not an object (evaluating 'preset.model')`. Root cause: localStorage had persisted `agentModePresets` without `debug` key from before the feature. Fix: bumped persist `version` to 2 (triggers migration) + added `?? fallback` in ModePresetCard for defensive rendering.

- [11:00] (Alek) fix: Agent didn't know it was in Debug mode — system prompt instructions not injected. Root cause: `stream-daemon.js` (the primary production code path) was not destructuring `debugMode` from the query command and not appending debug instructions to `systemPrompt.append`. Only `stream-claude.js` (legacy spawn path) had the fix. **KEY GOTCHA**: Quack has two parallel Node.js code paths — BOTH must be updated for any new config field. Documented in `documentation/gotchas/gotcha-daemon-missing-new-config-fields.md`.

- [11:10] (Alek) fix: Missing Debug option in ChatSettingsMenu popover (separate from CustomPermissionSelect) and Shift+Tab keyboard shortcut cycle.

- [11:15] (Alek) docs: Created `documentation/patterns/pattern-permission-modes.md` documenting the full 3-mode system architecture, data flow, and checklist for adding new modes. Created `documentation/gotchas/gotcha-daemon-missing-new-config-fields.md` documenting the dual-path gotcha.

- [17:30] (Alek) fix(remote): Mobile dashboard now mirrors Mac ordering for agent groups and agents. Added `/api/ordering` endpoint (reads `.quack-repo-order.dat` + `.quack-agent-order.dat`) and `/api/groups` endpoint (reuses `groups::list_groups()`). Named groups like "Quack" and "MEOW" now display correctly. Session dot color now mirrors Mac: uses `agent.status` (not `session.status`) — agent idle → green, agent busy + newest session → amber, no messages → gray. **KEY GOTCHA**: `session.status === 'in_progress'` means "open", NOT "actively working". See `documentation/gotchas/gotcha-mobile-session-dot-status.md`.

- [18:00] (Alek) fix(remote): Session dots still yellow after rebuild — root cause was browser caching. Safari iOS (PWA mode) cached old JS with `in_progress → working` mapping. Fix: added `Cache-Control: no-store` to JS/CSS responses in `remote_dashboard.rs`. Also simplified dot logic: `getSessionDotClass(agentStatus, isNewest)` — only uses agent status, no messageCount dependency.

- [23:00] (Alek) fix(stamina): Context Receipt "Messages" breakdown was wildly inaccurate — showed 26.8k instead of ~400 tokens after a single message. Root cause: `calculateProjectOverhead()` was a static file-based estimate (~35.6k) that missed `.claude/rules/` files, skills (~5k), and underestimated MCP tool definitions. Fix: measure overhead from first SDK response — `contextWindowFill` on turn 1 ≈ real overhead (messages are negligible). Stored as `measuredOverhead` in chatTokensMap, preferred over static estimate. See `documentation/gotchas/gotcha-stamina-overhead-static-estimate.md`.
