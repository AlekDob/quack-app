# 2026-07-14

## Chat file links — bare doc filename resolution

**Problem:** Clicking a blue inline file link (e.g. `035-astronaut-ios-native.md`) showed *doesn't exist yet*, while the Read tool drawer opened the same file — Read passes the full absolute path; chat linkify only keeps the basename.

**Fix (`workspaceDocOpen.ts`):**
- Candidate paths now scan **all open workspaces**, not only the active chat project.
- Bare `.md` names fall back to a documentation-tree basename search (`engine/documentation/features/…`, diary dates → `documentation/diary/`, etc.).
- Resolved files open in the owning workspace tab (switches project when needed).

Doc: `070-workspace-doc-open.md`.

## Plan mode + parallel subagents — permission flood + Auto flip

**Problem (reported):** Jack in Plan mode launching 3 Explore subagents still surfaced permission cards; clicking **Allow all** flipped the composer to **Auto** — defeating Plan + formal Build handoff.

**Root causes:**
1. `PLAN_EXPLORE_TOOLS` (2026-07-13) covered Task delegation but not subagent sidechain tools (`WebFetch`, `ToolSearch`, …) or harmless wait Bash (`sleep 1; echo done` blocked by `;` in old `BASH_CHAIN_RE`).
2. **Allow all** always called `setCcPermMode("auto")` even when the composer showed Plan.
3. `getPermModeFor(req)` alone could miss Plan when subagent `cwd`/`session_id` diverged from the chat — card showed **Allow all** instead of **Allow exploration**.

**Fix:**
- `ClaudePermissionOverlay` — `PLAN_READ_TOOLS`, `NotebookRead` in read-only hook set, `parent_tool_use_id` sidechain auto-allow, safer read-only Bash chains (`;`/`&&` when every segment is read-only), Plan-only **Allow exploration** (`planSessionExploreRef`, composer stays Plan).
- `AIChatPanel` — `ownerPermMode={ccPermMode}`; `panelPermMode()` prefers composer over `permModeStore`.
- `claude_perm.rs` — forward `parent_tool_use_id` / `parentToolUseID` on `PermissionRequest`.

**Verify:** `npm run build`; manual — Jack · Plan, launch parallel Explore subagents, confirm no card flood; click **Allow exploration**, composer chip stays Plan (not Auto).

Docs: `015-claude-permission-mode.md`, `004-subagent-mentions.md`, `061-plan-mode-tab.md`.

## Subagent transcripts — drawer pref + shared chat styling

**Problem:** Subagent read-only threads opened only as editor tabs / agent-mode 50-50 split, with custom `.subagent-msg-*` markup that didn't match the main chat (spacing, tool pills, user turns).

**Fix:**
- Settings → Views → **Subagent transcripts** (`lcp.surfaceView.subagent`, default **drawer**).
- `openSubagent` → `openSingletonSurface` (same tab/drawer flow as Works/Brain/Team).
- `focusedAgentSidePanelKey` skips `sub:` keys in `layout.editorDrawer` (no double render).
- Agent Mode: `EditorTabDrawer` + `TabContentHost` when pref = drawer; inline split only when pref = tab.
- `TranscriptTurnRows` — DRY read-only turns (`.ai-msg`, `.ai-user-bar`, `.ai-tcalls`, `ToolCallRow`).
- Drawer chrome: duck avatar + agent type for `sub:` keys.

**Verify:** `npm run build`; Settings → Views → Subagent transcripts → Side drawer; click Explore chip in a CC chat with parallel subagents; confirm drawer opens with matching tool pills.

Docs: `004-subagent-mentions.md`, `063-surface-view-prefs.md`.
