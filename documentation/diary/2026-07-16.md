- [08:54] (Alek) Fixed the "app freezes / 100% CPU on launch and chat switch" loop. Stack-sampled the pegged `target/debug/Quack` process → main thread stuck 100% in `provider_list_sessions → list_claude_sessions → summarize_jsonl → serde_json::from_str`. Root cause: the CC session drawer poll (`AIChatPanel` diskHydrate effect, 12s interval) calls `guessClaudeSessionId` whenever a chat has no saved `claudeSessionId`, which runs the **synchronous** `provider_list_sessions` Tauri command on the main thread — parsing the ENTIRE `~/.claude/projects/<proj>` dir line-by-line. With `~/.claude` at 1.1 GB / 1298 files (single files up to 98 MB), one call blocks the UI for seconds; on a failed guess it re-parsed every 12s forever. Fix (3 layers): (1) `provider_list_sessions`/`provider_load_session` → `async` + `spawn_blocking` (off the main thread — no UI freeze even cold); (2) per-file summary cache in `summarize_jsonl` gated on (mtime,size) so inactive JSONL is parsed once ever (mirrors the usage-monitor freeze fix, feature 019); (3) frontend `guessAttemptRef` so the guess runs once per distinct turn count, not every poll. Verified with a stack-sampling + CPU probe: `Quack` Rust 98%→5%, webview 83%→6% at idle. KEY INSIGHT: on macOS the Tauri webview is a separate `com.apple.WebKit.WebContent` process — when the Rust `Quack` process itself pegs a core, the culprit is backend/IPC, not React; a JS-only render/effect probe will (correctly) show nothing. `sample <pid>` on the Rust process is the fastest way to locate a backend main-thread block.
- [08:54] (Alek) NOTE / follow-up latent bug found while investigating: `src-tauri/src/watcher.rs` watches each workspace root with `RecursiveMode::Recursive` and **no ignore list** (target/, node_modules/, .git/, dotdirs). Any write under a root (builds, dev-server caches, git ops) floods `fs:event` → `gitStatusStore` runs `git status` per workspace + `FileTree`/`EditorPane` rescans → webview CPU. Not the freeze fixed above, but worth adding an ignore filter in the watcher.
- [09:07] (Alek) Added a gradual chat/session-switch loader (feature 075) so switching doesn't feel janky now that it's fast. Reworked `chatSwitch.ts`: the veil shows immediately on `pulseChatSwitch`, stays a graceful MIN floor (240ms) even if hydration is instant, ends via `endChatSwitch` (from `onHydrated`) after the floor, with a 1000ms cap fallback. `ChatSwitchVeil` now fades (translucent `--bg` wash + `backdrop-filter: blur` + slim indeterminate top bar) and stays mounted through the fade-out; hosts render it unconditionally with a foreground-gated `active` prop (`switching && visible`) so background panels never flash it. Triggers (`AgentModeShell.selectSession`, `AIChatsRail.focusChat`) now veil on EVERY switch, not just cross-workspace. KEY INSIGHT: the min-visible floor must live in the pulse store, not the component — otherwise fast hydration drops the veil in <100ms and it flashes; and the veil must stay mounted through fade-out (own `mounted` state) since the host flag flips off instantly.
