- [13:00] (Alek) **Fix AskUserQuestion empty answers regression dopo SDK 0.2.111 → 0.2.138** (commit `3d84a9e` di ieri). Causa root: SDK `0.2.113` ha rimosso il bundled `cli.js` e ora spawna sempre il native binary `@anthropic-ai/claude-agent-sdk-darwin-arm64`, il cui IPC zod-valida `updatedInput` di canUseTool contro `AskUserQuestionInput` schema (che ha solo `questions`) e strippa il campo `answers` aggiunto a runtime. Stesso class del bug 2026-05-04 ma il workaround di allora (forzare bundled) non si applica più. Workaround nuovo: PreToolUse hook (matcher `AskUserQuestion`) raccoglie answers dal frontend via `requestFromFrontend` e le stages in `pendingAskAnswers: Map<toolUseId, answers>`; canUseTool per AskUserQuestion bypassa (`return {behavior:'allow', updatedInput: input}`) per non ri-promptare il frontend (causa hang); PostToolUse hook (matcher `AskUserQuestion`) preleva answers e le inietta nel tool result via `additionalContext` (markdown list — `updatedToolOutput` provato prima ma silently dropped, sospetto schema-validation strict anche su output). Files: `src-tauri/node-sdk/stream-daemon.js` (+85 righe — map globale + 2 hooks + canUseTool simplification). Brain entry nuovo `documentation/bugs/fix-askuserquestion-sdk-0.2.138-pretool-posttool-hook.md`; vecchio `fix-askuserquestion-native-cli-strips-answers.md` marcato `superseded`. Aggiornato CLAUDE.md Knowledge Base. Feature doc `documentation/features/064-ask-tool.md` per centralizzare il flusso. Indagine ha richiesto rimettere mano a 2 ipotesi sbagliate (allowedTools step 4, updatedToolOutput JSON.stringify) — diagnosi confermata via `~/.quack/daemon-diag.log` con i log `PreToolUse staged answers` + `PostToolUse appending context`.
