- [14:00] (Fredric) Cache bisection investigation: tested whether Quack can drop persistent subprocess and use SDK `query()` per message (like the Kite reference app). Ran 5 test scripts with incremental option addition, string vs generator prompts, constant vs changing ideContext, and realistic user timing. KEY FINDINGS: (1) No individual Quack option breaks caching — systemPrompt.append, allowedTools, mcpServers, betas, env all produce >99% hits. (2) AsyncGenerator prompt format works fine. (3) With constant ideContext, query() per message matches persistent subprocess (~120-200 tokens cache create). (4) Changing ideContext causes ~6-7k cache_create per turn on cold starts — this is the gap vs persistent subprocess's ~230 tokens. Decision pending on whether to accept this trade-off. See `documentation/bugs/investigation-query-per-message-cache-bisection.md`.
