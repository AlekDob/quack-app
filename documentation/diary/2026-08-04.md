- (Alek) Ported the **quack completion sound** from codetta: `apps/web/public/sounds/quack.mp3` + `apps/web/src/lib/quackSound.ts` (cached `HTMLAudioElement`, rewind on replay, autoplay rejection swallowed). Fires once per batch in `taskCompletion.tsx` on chat-turn completion only — not for needs-input or terminal events.
- Key insight: the "completion sound" before this was never ours — it was the OS chime from `Notification({ silent: false })`. So the quack path passes `silent: true` on that same notification, otherwise you hear both. New setting `enableQuackCompletionSound` (default on) gates both the cue and the muting, so turning it off restores the OS chime.
- Added the **papero avatar to the chat transcript**: shown once, at the top of each assistant turn's block, fixed to whichever papero was active when that turn was written (Tab cycling mid-thread does not retarget past turns). Client-only fix — `paperoId` already existed on `OrchestrationMessage` server-side but the client silently dropped it; threaded it through `ChatMessage` (`types.ts`) and `storeNormalization.ts`, then derived a per-turn "avatar owner" in `MessagesTimeline.logic.ts` (`deriveMessagesTimelineRows`), hoisted through settled-turn folding so it survives collapsing multi-message turns. Reused the existing `PaperoAvatar` (exported from `PaperoPill.tsx`) instead of duplicating markup.
- Review caught a real regression before shipping: `isRowUnchanged` (row-stability diffing, used to avoid re-rendering unchanged virtualized rows) didn't compare the new `showPaperoAvatar`/`avatarPaperoId` fields, so a stale cached row could hide the avatar (or show a stale one) after a turn settles/folds. Fixed by adding both fields to the comparison.
- Living feature doc: `documentation/features/003-paperi.md`
- Added **duck avatars for subagents** (Explore/Agent-tool spawns, dynamic workflow runs) — same deterministic hash pattern as the papero avatar, but for subagent identity, not the top-level composer agent. `duckAvatarFor` (from `apps/web/src/lib/duckAvatars.ts`) had already been ported from codetta with zero callers; wired it up via a new shared `SubagentAvatar` component.
- Covered all three surfaces where a subagent shows up: the composer running-subagent strip (`ComposerSubagentStrip.tsx`), the dynamic-workflow agent row (`WorkflowRunCard.tsx`), and the transcript's `collab_agent_tool_call` tool-call row (`TimelineWorkEntryRow.tsx`, swaps the generic bot icon for the duck).
- Same subagent name/type seeds the same duck across all three surfaces (no shared state needed — pure function of the subagent's existing identity fields, computed inline in JSX).
- Living feature doc: `documentation/features/005-subagent-avatars.md`
