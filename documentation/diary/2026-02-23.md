- [PM] (Alek) Fix "Object not disposable" crash in production — Root cause: production finds /usr/local/bin/node v18 first (Homebrew), which lacks Symbol.dispose. ESM hoisting prevents inline polyfill from working. Three-pronged fix: (1) Node resolution now collects ALL candidates and picks highest major version (nvm v22 > Homebrew v18), (2) MIN_NODE_VERSION bumped 18→20, (3) CJS polyfill loaded via --require for Node 20-21 (runs before ESM evaluation, solving hoisting). Files: claude_cli.rs, prerequisites.rs, disposable-polyfill.cjs
- [Feature] (Alek) Multi-provider support: Ollama + custom endpoints — Added LLM provider selection (Anthropic/Ollama/Custom) in Settings. Ollama models discoverable via /api/tags. Backend injects ANTHROPIC_BASE_URL env var per provider. Zero impact on existing Anthropic flow. Files: types.ts, settingsStore.ts, ollamaService.ts (new), claude_cli.rs, stream-claude.js, ClaudeCodeSettings.tsx, ChatSettingsMenu.tsx, App.tsx, usePopoutKanbanChat.ts, claudeSDK.ts
- [Feature] (Alek) Brain Read indicator in stream chat — When an agent reads a Brain file (documentation/ or ~/.quack/brain/) via Read/Glob/Grep, the tool call now shows a rosa "Brain" badge pill with tinted background, making knowledge access visible. Utility isBrainRead() detects Brain paths. Files: brainPathDetection.ts (new), StreamMessage.tsx, ToolCallMinimal.tsx, ToolCallMinimal.css
- [Fix] (Alek) Model name display for non-Anthropic providers — Footer, message badges, and chat header were showing "Opus 4.6" when using Ollama models. Root cause: hardcoded `'opus46'` fallback in multiple locations. Fixed with `getActiveModelName()` which checks the active provider. Files: claudeSDK.ts, App.tsx, ChatSettingsMenu.tsx, MessageSettingsBadges.tsx
- [UI] (Alek) Provider settings UI polish — Redesigned Ollama status indicator (pill badge with glow), refresh button (SVG icon with rotation on hover), and disclaimer (compact with warning icon and orange border). Files: ClaudeCodeSettings.tsx
- [Docs] (Alek) Brain update: multi-provider documentation — Created pattern (pattern-multi-provider-llm.md), gotcha (gotcha-model-name-non-anthropic-provider.md), and decision (decision-ollama-multi-provider-integration.md) docs for the Ollama integration
