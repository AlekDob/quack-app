How we turned an open-source CLI middleware into a native Quack feature
April 1, 2026 · quack-app
The Inspiration
OpenWolf is an open-source middleware that sits between developers and Claude Code. It uses 6 hooks to automatically track file reads/writes, surface project knowledge before actions, and prevent repeated mistakes. They claim 65-80% token reduction through intelligent caching and pre-read intelligence.

We studied their architecture and cherry-picked the best ideas — then adapted them to work natively inside Quack, where our existing Brain system (220+ knowledge entries) already had the data but lacked the automation.

Three-Layer Architecture
Unlike OpenWolf (CLI-only), we built a three-layer system where two layers work natively for every Quack user with zero setup:
UI Banner
BrainContextBanner in ChatView — shows stats, stale warnings, last diary. Visible on every empty session.
Native ✓
Auto-Diary
brainSessionService hooks into sessionStore.markDone() — appends diary entry with title, messages, duration.
Native ✓
CLI Hooks
4 Node.js hooks (pre-read, pre-write, session-start, stop) — feed Brain context to Claude invisibly.

Expected Impact
💰Token Savings
Repeated reads flagged with token cost. Pre-read shows AST summary before full file reads. OpenWolf claims 65% reduction.

220+ gotchas/bugs surfaced automatically before writes. Brain breadcrumbs resolved in real-time. No more silent regressions.
