- [10:00] (Alek) Aggiornata skill-creator da v1.0.0 a v2.0.0 (synced con anthropics/skills upstream). Nuova versione include eval workflow, benchmark viewer, description optimization, blind A/B comparison, agents specializzati (grader/comparator/analyzer). Aggiornato anche su quack-marketplace e pushato.

- [10:30] (Alek) Implementato sistema di versioning + update per il Quack Store. Tre problemi risolti: (1) nessun tracking delle versioni installate, (2) skill installate solo con SKILL.md ignorando scripts/references/assets, (3) nessun meccanismo di update nell'UI. Soluzione: registry JSON centralizzato (`~/.claude/plugins/quack-installed.json`), download completo directory skill via GitHub Contents API con fallback, badge "Update vX.Y.Z" arancione nella card e bottone nel modal. File creati/modificati: `marketplaceRegistryService.ts` (nuovo), `useMarketplace.ts`, `MarketplaceCard.tsx`, `MarketplaceInstallModal.tsx`, `MarketplaceDrawer.tsx`. KEY INSIGHT: retrocompatibilità gestita con versione "unknown" per installazioni pre-registry — nessun falso positivo di update.

- [11:00] (Alek) feat: skill `youtube-transcript` creata per il Quack Store. Usa yt-dlp come backend (auto-install), supporta multi-lingua, sottotitoli manuali/auto-generati, capitoli. Script Python (~190 righe) con output JSON strutturato. 8 eval test cases. Testato su 2 video reali.

- [11:15] (Alek) feat: ComponentRegistry pattern per structured outputs. Sostituisce la catena if/else hardcoded in StreamMessage.tsx con un registry generico type-guard-based. Nuovi tipi si registrano in index.ts senza toccare StreamMessage. BugReport e WebAnalysis invariati.

- [11:20] (Alek) feat: TranscriptViewer component — header video, summary collassabile, capitoli cliccabili, transcript scrollabile con ricerca e timestamp copiabili. Stile glassmorphism coerente con BugReportWidget.

- [11:30] (Alek) feat: json-render (Vercel) integrato in Quack. Pacchetti: @json-render/core + @json-render/react + zod. QuackCatalog con 17 componenti (Card, Section, Columns, Heading, Text, Badge, CodeBlock, Image, Table, Metric, ProgressBar, List, KeyValue, Link, Button, Tabs, Alert) + QuackRegistry (implementazioni React dark-theme) + JsonRenderAdapter (bridge con ComponentRegistry, priority 1 = fallback generativo). L'AI puo' ora generare UI strutturate via JSON spec `{ root, elements }`.

- [12:30] (Alek) feat: implementato pattern WebSocket per il modulo remote (`remote_ws.rs`). WsBroadcast basato su `tokio::sync::broadcast` con capacity configurabile. Autenticazione via query param `?token=xxx` prima dell'upgrade. Due task Tokio in parallelo (send + recv) con `tokio::select!` per gestire disconnect. 5 tipi di evento: `agent_status`, `session_created`, `session_completed`, `job_fired`, `job_completed`. KEY INSIGHT: il broadcast channel è clonato nell'axum state; i sender vivono in `lib.rs` nei listener Tauri — questo decoupling evita lock e permette emit da qualsiasi punto del backend senza passare riferimenti al WS handler.
