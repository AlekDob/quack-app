# 2026-02-09 - Quack Dev Diary

## Git Config Onboarding - Planning Phase

Discusso con Alek l'implementazione di un controllo obbligatorio della configurazione Git durante il primo avvio di Quack.

### Requirement

Durante il primo avvio (sia Mac che Windows):
1. Verificare se `user.name` e `user.email` sono configurati in Git
2. Se non configurati, mostrare una schermata di onboarding obbligatoria
3. Dopo la configurazione Git, procedere con la selezione dell'IDE preferito

### Architettura Scoperta

**IDE Onboarding esistente**:
- Componente: `IDEOnboarding.tsx`
- Store: `ideStore.ts` (Zustand) con `hasCompletedOnboarding` flag
- Selector: `selectShouldShowOnboarding` verifica se mostrare l'onboarding
- Rendering: `App.tsx` mostra `<IDEOnboarding />` condizionalmente
- Pattern: modal fullscreen con rilevamento automatico IDE, selezione obbligatoria

**Git Commands Rust**:
- File: `src-tauri/src/git.rs`
- Funzione helper: `run_git()` per eseguire comandi Git
- Pattern: `run_git(&root, &["config", "--get", "remote.origin.url"], false)?`
- Esiste già infrastruttura per leggere config Git

### Piano di Implementazione

**Task List**:
1. Backend Rust — comandi Tauri per check/set Git config
2. Frontend — `GitConfigOnboarding.tsx` componente
3. Store — `gitStore.ts` con Zustand per state management
4. Integrazione — modificare `App.tsx` per sequenza: Git → IDE

**Flusso di Onboarding**:
```
Prima:  Splash → IDE Onboarding (se non configurato) → App
Ora:    Splash → Git Config (se non configurato) → IDE Onboarding (se non configurato) → App
```

**Design Pattern da Seguire**:
- Same UI style di `IDEOnboarding` (fullscreen, backdrop, card layout)
- Nessun "Skip" button (obbligatorio)
- Form validation: nome non vuoto, email formato valido
- Optimistic update con rollback on error (pattern da `ideStore`)

### Insight: Onboarding Sequenziale

L'architettura attuale usa **single boolean flags** (`hasCompletedOnboarding`) per ciascun onboarding step. Per gestire sequenze (Git → IDE), ciascun componente verifica il proprio flag indipendentemente.

**Pattern attuale (IDE)**:
```typescript
selectShouldShowOnboarding = !hasCompletedOnboarding && preferredIDE === null
```

**Pattern futuro (Git)**:
```typescript
selectShouldShowGitConfig = !hasConfiguredGit && (!gitUserName || !gitUserEmail)
```

L'ordine di rendering in `App.tsx` garantisce la sequenza corretta (Git prima, IDE dopo).

### Decisione Architetturale: Global vs Local Git Config

**Scelta**: usare `--global` flag per configurare Git a livello utente, non a livello repository.

**Rationale**:
- L'onboarding avviene al primo avvio di Quack, non quando si apre un progetto specifico
- `user.name` e `user.email` sono configurazioni personali, non project-specific
- Git richiede queste configurazioni per qualsiasi commit, indipendentemente dal repo
- Una volta configurato globalmente, funziona per tutti i progetti futuri

**Comando**: `git config --global user.name "..."` (non `git config user.name "..."`)
