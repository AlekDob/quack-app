# 2026-02-05 — Two-Level Brain Architecture + Preferred Skills System + Marketplace Expansion

## Lavoro Completato

### 1. Two-Level Brain Architecture Migration
**Problema**: Tutto il brain viveva in `~/.quack/brain/projects/{project-name}/`, causando:
- Retrieve di info irrilevanti (contaminazione cross-project)
- Difficoltà nel distinguere conoscenza project-specific vs personale
- Non condivisibile col team

**Soluzione implementata**: Brain a 2 livelli
1. **Project Brain** (`{project}/.quack/brain/`) - Conoscenza specifica del progetto
   - NON gitignored - condivisibile col team
   - Contiene: bugs/, patterns/, decisions/, gotchas/, diary/, inbox/, map.md
   - Search priority 1 (consultato per primo)

2. **Global Brain** (`~/.quack/brain/global/`) - Conoscenza personale cross-project
   - Contiene: patterns/, preferences/, people/, tools/
   - Search priority 2 (fallback quando project brain non ha risposta)

**Migrazione completata** per tutti i progetti attivi:
- `quack-app`: 108 files
- `flow-bi`: bugs, decisions, diary, gotchas, notes, patterns, tools
- `safehood`, `quackagency-website`, `new-project`, `studio-futuro`: vari file

**File aggiornati**:
- `.claude/rules/use-quack-brain.md` (quack-app, global, marketplace)
- `quack-marketplace/plugins/quack-brain/skills/quack-brain/SKILL.md`
- `quack-marketplace/plugins/use-quack-brain/rules/use-quack-brain.md`

**Commit marketplace**: `a35231a` - "refactor(quack-brain): implement two-level architecture"

**Vantaggi**:
- Retrieve più mirato e veloce
- Niente inquinamento cross-project
- Project brain condivisibile (team knowledge base)
- Global brain personale (preferenze, persone, tools)

### 6. Active Agents Index System (Performance + Consistency)
**Problema**: Discrepanza tra `npm run dev` e `npm run build` - agenti mostrati diversi.

**Causa**: Terminali attivi salvati in localStorage separato per ambiente (dev ≠ build).

**Soluzione**: File `.quack/active-agents.json` condiviso
```json
["uuid-1", "uuid-2", "uuid-3"]
```

**Implementazione**:
1. **Rust (`personality.rs`)**:
   - `load_active_agents()` - Carica lista ID
   - `save_active_agents()` - Salva lista ID
   - `add_active_agent()` - Aggiunge ID
   - `remove_active_agent()` - Rimuove ID

2. **TypeScript (`terminalStorage.ts`)**:
   - Wrapper per funzioni Rust
   - `migrateToActiveAgentsIndex()` - Migrazione automatica dal vecchio sistema

3. **App.tsx**:
   - `handleCloseTerminal` → chiama `removeActiveAgent`
   - 6 punti di creazione terminale → chiamano `addActiveAgent`

**Vantaggi**:
- Consistenza garantita dev/build (stesso file)
- Performance: 1 sola lettura all'avvio (file leggero)
- Backward compatible (migrazione automatica)
- Debug facile (guardi il file JSON)

### 7. Model Management - Zero Code Changes Policy
**Problema**: Dopo aver aggiornato i modelli in Supabase (Opus 4.6, Sonnet 5), richiedeva modifiche al codice in `modelService.ts`.

**Soluzione**: EMERGENCY_FALLBACK minimale
- Rimossi tutti i modelli hardcoded (`opus46`, `sonnet45`, `haiku45`)
- Rimossa legacy ID map
- Solo Sonnet come fallback di emergenza se Supabase offline

**Per aggiornare modelli in futuro**:
1. Supabase → `app_config` → modifica chiave `models`
2. **Basta!** L'app carica automaticamente

## Pattern Applicati

1. **Two-Level Knowledge Architecture** - Project-specific vs Cross-project separation
2. **Zero Code Changes Policy** - Configurazione remota via Supabase per modelli
3. **Skill-First Agent Design** - Skills come killer feature, droids/commands deprecati
4. **Inline Editing Pattern** - Form integrato in selector invece di step separato
5. **Consistency via Shared State** - `.quack/active-agents.json` elimina discrepanze
6. **Auto-Migration Pattern** - Backward compatibility garantita durante refactor
7. **Icon-Based Visual Hierarchy** - Stella arancione (skills) vs robot azzurro (droids)
8. **Agent Communication Protocol** - Best practice 2026 auto-iniettate

---

## Decisioni Architetturali

1. **Project Brain NON gitignored** - Condivisibile col team, team knowledge base
2. **Global Brain personale** - Preferenze, persone, tools cross-project
3. **Skills > Droids/Commands** - Futuro di Quack è skill-based
4. **Marketplace sempre visibile** - Templates disponibili in ogni creazione agent
5. **Active agents index in filesystem** - Performance + consistenza + debug facile
6. **Emergency fallback minimale** - Solo Sonnet se Supabase offline
