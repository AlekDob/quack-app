# 2026-02-13

## Fixed Stamina Context Receipt Messages: 0 (CORRECT fix)

First attempt used modelUsage fallback — WRONG. The real root cause has TWO parts:

### 1. Prompt caching makes `input_tokens` misleading
With prompt caching, `usage.input_tokens` = only non-cached tokens (e.g., 24). The real context fill is:
```
context_fill = input_tokens + cache_read_input_tokens + cache_creation_input_tokens
```

### 2. Result event usage is cumulative, not per-turn
Result event sums all agentic steps. For context fill display, must use assistant message usage (per-step).

### Fix applied
- `handleTokenUpdate`: `inputTokens = input_tokens + cache_read + cache_creation`
- `handleClaudeEvent`: Extract usage from assistant events (per-step), not result events
- Removed wrong modelUsage fallback from Rust + React
- Same fix in useClaudeChat.ts

See bugs/fix-stamina-messages-zero-modelusage-fallback.md for complete details.

## Fixed Auto-Compact Percentage Discrepancy

Discovered that Total percentage was inflated by 45k (AUTO_COMPACT_COST). CLI showed 36k/200k (18%) but Quack showed 80.7k/200k (40%). Removed AUTO_COMPACT_COST from totalContextUsage in StaminaBarBorder.tsx and TokenUsageModal.tsx. Now Total matches CLI `/context` output. AUTO_COMPACT_COST is still subtracted from FREE calculation (correctly constraining available tokens) but no longer inflates the percentage.

## Fixed Stamina Reset on App Restart

Problem: `chatTokensMap` was a volatile `useState<Map>` — lost on restart. `AgentSession` already had token fields (`inputTokens`, etc.) and was persisted via `sessionStore`, but tokens were never saved there.

Fix:
- **Save**: Persist tokens to `sessionStore` in result event handler and backup invoke path (both in `handleClaudeEvent` and `sendMessageForAgent`)
- **Restore**: At bootstrap (after `loadSessions`), repopulate `chatTokensMap` from persisted session tokens
- Deliberate choice to persist only on result event (end of turn) to avoid excessive disk writes
