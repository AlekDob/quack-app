# 2026-02-08 - Git Branch Real-Time Watcher

## Problem Identified
Agent Graydon reported: when an agent runs `git checkout` to another branch via CLI, the branch indicator in the right panel stays stuck on the old branch. New sessions show the correct branch because they read fresh from disk.

## Root Cause Analysis
- `App.tsx` useEffect at line 1403 reads `activeTerminal.branch` (priority) or fallback `git_current_branch()`
- Dependencies: `[activeTerminal, tauriAvailable]` — neither changes when git state changes on disk
- Result: stale closure, UI shows old branch even after successful checkout

## Solution Implemented
Created `GitBranchWatcherManager` in Rust using existing `notify 8.2` crate:
- Watches `.git/HEAD` file (30 bytes, changes only on checkout)
- NonRecursive mode, 200ms debounce
- Reads branch directly from file (no git command spawn)
- Handles worktrees (`.git` as file with gitdir reference)
- Emits `git:branch-changed` Tauri event

Frontend changes in `App.tsx`:
- Start watcher lazily when terminal activates (idempotent)
- Listen for `git:branch-changed` event
- Update both `gitBranch` state (UI) and `terminals` array (persistence)
