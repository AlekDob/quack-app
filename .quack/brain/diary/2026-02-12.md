## Fixed agent-bundle installation flow (CORRECT VERSION)

Project picker now preserved and working. Root issue was UnifiedAgent in Tauri store not connecting to sidebar terminals.

### Root Cause
When installing agent-bundles from the store, the agent would be created in the Tauri store but wouldn't appear in the sidebar with a working terminal. The project picker modal was showing but the installed agent lacked proper terminal connection.

### Solution
Added `onAgentBundleInstalled` callback chain:
1. **QuackStoreDrawer.tsx**: Passes callback to parent (App.tsx)
2. **App.tsx**: Handler that creates proper terminal in sidebar:
   - Calls `invoke('create_terminal')` to create Rust-side terminal
   - Updates React state with `setTerminals`
   - Injects agent personality into terminal

### Flow
1. User clicks "Get" on agent-bundle in store
2. Picks project from modal
3. Skills/rules installed globally to `~/.claude/`
4. Agent appears in sidebar with working terminal, ready to use

### Bonus Fix
Fixed StoreProjectPickerModal scroll overflow with max-height constraints.

### Files Changed
- **useMarketplace.ts**: Return arrays for proper callback handling
- **QuackStoreDrawer.tsx**: Added `onAgentBundleInstalled` callback prop
- **App.tsx**: Implemented callback handler with terminal creation
- **StoreProjectPickerModal.tsx**: Fixed scroll overflow

## Fixed 6 critical team system bugs

Comprehensive session fixing bugs that prevented teammate interaction, caused infinite render loops, and unintended git sharing of team configurations.

### Bug Fixes Applied

1. **TeammateWidget drill-down not clickable after completion**
   - File: `src/components/TeammateWidget.tsx:29`
   - Removed `isStarting` from `isClickable` condition
   - Added "(click to view)" hint to completed state

2. **SessionId lost when teammate stops**
   - File: `src/App.tsx:1228`
   - Pass `agentEvt.session_id` on stop events to preserve session reference

3. **IDEOnboarding infinite render loop** (Maximum update depth exceeded)
   - File: `src/components/settings/IDEOnboarding.tsx`
   - Root cause: bare `useIDEStore()` destructuring + store updates in effect = infinite loop
   - Fixed with individual selectors, `hasLoadedRef` guard, memoization
   - This was blocking ALL sidebar rendering including team badges

4. **Team files shared via git** (colleague sees ghost teams)
   - File: `.gitignore`
   - Added `.quack/teams/` to gitignore
   - Ran `git rm --cached` on 5 team JSON files

5. **Team avatar enrichment race condition on startup**
   - File: `src/components/RepositoryGroup.tsx:1189-1196`
   - Added second `useEffect` watching `agentCount`
   - Re-calls `loadActiveTeam` when agents become available

6. **TeammateWidget sessionId not reactive in Task tool path**
   - File: `src/components/StreamMessage.tsx:371,529`
   - Changed from `useTeamStore.getState().teammateStatus` (static) to reactive selector
   - Widget now re-renders when agent event arrives and updates store

### Key Insights
- `npm run dev` (Vite only) cannot load teams - no Tauri/Rust backend. Use `npm run tauri dev`
- Zustand `getState()` is NOT reactive - always use selectors for dynamic data
- Team JSON persistence works correctly - all issues were frontend rendering/reactivity bugs
- Agent events may arrive after initial render - UI must be reactive to store updates

## Fixed Stamina Context Receipt - Messages: 0 bug

Completed comprehensive fix for stamina widget showing zero messages despite token consumption. See bugs/fix-stamina-context-receipt-messages-zero.md

### Root Causes (3 independent bugs)
1. **Rust null deserialization** - Claude SDK sends `cache_*_tokens: null`, Rust `#[serde(default)]` only handles missing fields. Added custom deserializer mapping `null → 0`
2. **Missing chatTokensMap update** - `trackUsage()` updated `usageSessions` but not `chatTokensMap` (the UI source). Added `handleTokenUpdate()` call after invoke completes
3. **Inconsistent calculations** - StaminaBarBorder was double-counting tokens (adding overhead when it was already included). Aligned math to TokenUsageModal's proven logic

### Files Modified
- `src-tauri/src/claude_cli.rs` - Custom serde deserializer + modelUsage field
- `src/App.tsx` - handleTokenUpdate in invoke response path
- `src/components/StaminaBarBorder.tsx` - Unified calculation logic

### Key Insight
Token flow is a chain: SDK → Rust parsing → Tauri event → React listener → handleTokenUpdate → chatTokensMap → UI. This bug had THREE breaks simultaneously.
