# 2026-02-11 - Quack Dev Diary

## macOS Release Build: Refactoring Completo Firma e Notarizzazione

Refactored completamente il sistema di build/signing/notarizzazione per macOS, rimuovendo tutti i valori hardcoded e centralizzando la configurazione nel `.env` con gestione sicura delle credenziali via Keychain.

### Problema Originale

Gli script di release (`release-macos.sh`, `sign-all-binaries.sh`, `sign-for-notarization.sh`, `release.sh`) avevano dati hardcoded:

- Project root: path assoluto del developer originale
- Signing identity: certificato Developer ID hardcoded
- Keychain profile: `QuackNotarization`
- Releases repo: hardcoded

Impossibile per altri developer buildare release con la propria identità.

### Soluzione: `.env` + Keychain + Path Dinamici

#### 1. Variabili Centralizzate

Tutte le configurazioni ora nel `.env`:

```bash
export APPLE_SIGNING_IDENTITY="Developer ID Application: Your Name (TEAM_ID)"
APPLE_KEYCHAIN_PROFILE="QuackNotarization"
GITHUB_RELEASES_REPO="YourOrg/quack-releases"
```

#### 2. Path Dinamici

Ogni script calcola `PROJECT_ROOT` dinamicamente:

```bash
SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
PROJECT_ROOT="$(cd "$SCRIPT_DIR/.." && pwd)"
```

#### 3. Credenziali nel Keychain (Non nel `.env`)

Le credenziali sensibili (`APPLE_ID`, `APPLE_PASSWORD`, `APPLE_TEAM_ID`) **rimosse dal `.env`** e salvate nel macOS Keychain:

```bash
xcrun notarytool store-credentials "QuackNotarization" \
  --apple-id "your@email.com" \
  --password "xxxx-xxxx-xxxx-xxxx" \
  --team-id "XXXXXXXXXX"
```

Questo crea un profilo nel Keychain accessibile a `notarytool` senza esporre password in plaintext.

### Gotcha: Process Substitution e Quote

**Problema**: Il parsing iniziale del `.env` usava `source <(grep | sed)` che rompeva quando le variabili contenevano apostrofi:

```bash
# Falliva con nomi contenenti apostrofi nella signing identity
source <(grep -v '^\s*#' .env | sed 's/^export //')
```

**Root cause**: la process substitution `<(...)` perde il contesto delle virgolette durante il parsing.

**Fix**: `source` diretto del file invece di process substitution.

```bash
# Gestisce correttamente apostrofi e virgolette
set -a
source "$PROJECT_ROOT/.env"
set +a
```

### Tauri Signing: signingIdentity null + Env Var

`src-tauri/tauri.conf.json` aveva l'identità hardcoded:

```json
"signingIdentity": "Developer ID Application: <nome e team ID hardcoded>"
```

**Fix**: impostata a `null` per usare la variabile d'ambiente.

```json
"signingIdentity": null
```

Tauri legge automaticamente `APPLE_SIGNING_IDENTITY` dall'environment.

### Problema: Tauri Tenta Notarizzazione Automatica

Quando `APPLE_ID`/`APPLE_PASSWORD`/`APPLE_TEAM_ID` sono nell'environment, Tauri tenta la notarizzazione automatica **prima** che i binari embedded (ripgrep, sharp, libvips) vengano firmati → Apple rejection.

**Soluzione**: script helper `load-signing-env.sh` che esporta **solo** `APPLE_SIGNING_IDENTITY`:

```bash
#!/bin/bash
# Load only APPLE_SIGNING_IDENTITY from .env for Tauri build.
# We intentionally DO NOT export APPLE_ID/APPLE_PASSWORD/APPLE_TEAM_ID
# because Tauri would attempt automatic notarization, which fails.

SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
ENV_FILE="$SCRIPT_DIR/../.env"

if [ -f "$ENV_FILE" ]; then
    IDENTITY=$(grep 'APPLE_SIGNING_IDENTITY=' "$ENV_FILE" | sed 's/^export //' | cut -d= -f2- | sed 's/^"//;s/"$//')
    if [ -n "$IDENTITY" ]; then
        export APPLE_SIGNING_IDENTITY="$IDENTITY"
    fi
fi
```

### Nuovo Script: `sign-and-notarize.sh`

Script post-build che gestisce firma completa + notarizzazione + creazione DMG:

**7 Step Pipeline**:

1. Rimuove JetBrains plugin (JAR non firmabili)
2. Firma **tutti** i binari in parallelo (ripgrep, sharp, libvips, .dylib, .node, Mach-O)
3. Verifica firma
4. Notarizza `.app` + staple ticket
5. Crea DMG con `.app` notarizzato (usa `create-dmg` se disponibile)
6. Firma DMG + notarizza DMG + staple ticket
7. Verifica finale (`source=Notarized Developer ID`)

### Comandi NPM

Nuovi comandi per release:

```json
"tauri:build": "source ./scripts/load-signing-env.sh && npm run build:secure && cargo tauri build && ./scripts/optimize-bundle.sh",
"tauri:build:release": "source ./scripts/load-signing-env.sh && npm run build:secure && cargo tauri build --bundles app && ./scripts/sign-and-notarize.sh",
"tauri:build:release:universal": "source ./scripts/load-signing-env.sh && npm run build:secure && cargo tauri build --target universal-apple-darwin --bundles app && ./scripts/sign-and-notarize.sh"
```

### Problema: Tauri Cancella il .app Dopo Aver Creato il DMG

`cargo tauri build` con target `dmg` crea il DMG e poi **cancella** il `.app` → `sign-and-notarize.sh` non trova nulla.

**Fix**: per le release, buildare con `--bundles app` (solo .app, no DMG). Il DMG lo crea `sign-and-notarize.sh` dopo la notarizzazione.

### Workflow Finale

```
npm run tauri:build:release
  ↓
1. load-signing-env.sh esporta APPLE_SIGNING_IDENTITY
  ↓
2. Tauri builda .app (firma solo main binary)
  ↓
3. sign-and-notarize.sh
  ├─ Rimuove JetBrains plugin
  ├─ Firma tutti i binari embedded (parallelo)
  ├─ Notarizza .app con Apple
  ├─ Crea DMG branded (con .app notarizzato)
  ├─ Firma e notarizza DMG
  └─ Verifica: source=Notarized Developer ID
  ↓
Deliverable: Quack.dmg (notarizzato, pronto per distribuzione)
```

### Binari Embedded Firmati

Il nuovo script firma **tutti** i binari third-party che Tauri ignora:

- `ripgrep/*/rg` (arm64 + x86_64)
- `ripgrep/*/ripgrep.node`
- `sharp-darwin-*/lib/*.node`
- `sharp-libvips-darwin-*/lib/*.dylib`
- Tutti i `.dylib`, `.node`, Mach-O executables nel bundle

### Verifiche

**Firma .app**:
```bash
codesign --verify --deep --strict Quack.app
spctl -a -vvv -t install Quack.app
```

Output: `source=Notarized Developer ID`

**Firma DMG**:
```bash
spctl -a -vvv -t install Quack.dmg
```

Output: `source=Notarized Developer ID`

**Binari embedded**:
```bash
codesign --verify Quack.app/Contents/Resources/node-sdk/node_modules/@anthropic-ai/claude-agent-sdk/vendor/ripgrep/arm64-darwin/rg
```

Passa senza errori (firmato con hardened runtime + timestamp).

### Security Migliorato

**Prima**: `.env` conteneva password Apple in plaintext.

**Dopo**:
- `.env` contiene solo signing identity + nome profilo Keychain
- Password nel macOS Keychain (accesso controllato da sistema)
- Nessuna credenziale sensibile in git o file di testo
